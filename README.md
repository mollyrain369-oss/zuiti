# 嘴替 · 评价工作台

> 消费完只有碎碎念？发出去得是段像样的话。

一个纯前端的消费评价生成工作台：把饭桌上、理发店里、收货时脑子里的零散口语，按品类维度重组、按平台文体包装，输出可直接发布到大众点评 / 小红书 / 朋友圈的评价。

**在线使用：** https://mollyrain369-oss.github.io/zuiti/

## 它解决什么问题

写好评/差评的真实痛点不是"不会写字"，而是三件事：

1. 感受是碎的——"菜咸、等得久、服务员还行"，不知道怎么组织
2. 场景不一样——评价餐厅看口味，评价 Tony 看技术和推销，维度完全不同
3. 语气难拿捏——差评写狠了像恶意攻击，好评写飘了像托

嘴替的做法：**26 个生活场景品类、130 条维度规则库打底，大模型只负责润色**。

## 核心设计

- **规则库优先，离线可用**：品类库（26 品类）→ 维度库（130 条，每条含关键词、正/负表达）→ 文体层（4 档语气 × 5 种平台文体）。不填 API Key 也能出稿。
- **大模型可选**：填 OpenAI 兼容接口（DeepSeek / 通义 / Kimi）的 Key 即走 LLM 润色，规则库自动拼装为结构化提示词；调用失败自动回落离线引擎。
- **生成后自动质检**：方法论固化成代码——套话检测、感叹号配额、字数区间、**数字事实越界**（正文出现原文没有的金额/时长即标记，防 AI 编造）、语气一致性，逐项 ✓✗ 展示。
- **数据本地化**：历史记录、API Key 均存浏览器 localStorage，无后端、不上传。

## 迭代记录（三次踩坑）

| 轮次 | 问题 | 结论 |
|---|---|---|
| v1 | 按情绪重排用户原句，打断了"我说要狼尾，结果剪成学生头"的因果 | 保留用户叙述顺序，定调只交给开头结尾 |
| v2 | 选"好评"但正文全是差评，开头仍写"整体是满意的"，自相矛盾 | 定调与内容自动对齐，冲突时降级中性表述 |
| v3 | 原文只有"还可以"时，三段式模板每段只剩几个字，拼成碎块 | 短输入走融合模式，整句一气呵成 |

## 技术

单文件 HTML（约 35KB），零依赖、零构建、双击即用；规则库以数据结构内置，可一键导出 CSV 导入飞书多维表格。
